# Accessibility criteria for new UI (WCAG 2.1 AA, distilled)

Write each item that applies as an `NF-n [a11y]` criterion, or as an AC when it's a
specific interaction. Name the surface; leave the technique to the implementer.

| Check | Criterion shape |
| --- | --- |
| **Keyboard** | The system SHALL make every new control reachable with Tab and operable with Enter/Space; Esc closes an overlay. |
| **Focus visible and ordered** | WHEN an overlay opens, the system SHALL move focus into it, and return focus to the trigger when it closes. |
| **Hover-only content** | The system SHALL show popover content on keyboard focus as well as on hover. |
| **Async feedback announced** | WHEN a background action finishes, the system SHALL announce the result to assistive technology without moving focus. |
| **Not colour alone** | The system SHALL convey severity by label or icon in addition to colour. |
| **Contrast** | Text SHALL meet 4.5:1 (3:1 for large text and UI glyphs), in both the dark and light themes. |
| **Target size** | Interactive targets SHALL be at least 24×24 px. |
| **Names** | Icon-only controls SHALL have an accessible name equal to their tooltip text. |
| **Reduced motion** | WHERE the OS requests reduced motion, the system SHALL disable non-essential animation. |
| **Reflow** | At a 390 px width, the system SHALL show the surface without horizontal page scroll. |

If the product has more than one theme (dark/light), any new colour must pass in each.
